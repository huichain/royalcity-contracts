# Redeem Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let investors burn Closed-property shares for a pro-rata share of an explicit redemption pool, auto-paying pending revenue first.

**Architecture:** Extend `Property` with `redemptionPool`. Treasury/manager deposits PAYMENT_TOKEN after `closeProperty`. `redeem` settles revenue (reuse claim path), pays `shares * pool / supply`, burns shares, reduces pool. Pause does not block redeem.

**Tech Stack:** Foundry, Solidity 0.8.30, OpenZeppelin ERC1155Supply + AccessControl + SafeERC20 (existing `RoyalCityRealEstate.sol`).

**Spec:** `docs/superpowers/specs/2026-09-19-redeem-design.md`

## Global Constraints

- Redeem only when `PropertyState.Closed`.
- `depositRedemption` auth matches `depositRevenue` (`TREASURY_ROLE` or `MANAGER_ROLE`).
- Auto-settle and pay pending/accrued revenue inside `redeem` before burn.
- Global / per-property pause must not block `redeem`.
- No oracle / fixed share price / redeem while still only `Funded`.
- Follow TDD: failing tests before production code for each behavior task.
- Do not commit unless the user asks (user prefers explicit commit requests).

```solidity
function depositRedemption(uint256 propertyId, uint256 amount) external nonReentrant {
    if (!hasRole(TREASURY_ROLE, msg.sender) && !hasRole(MANAGER_ROLE, msg.sender)) {
        revert UnauthorizedDepositor();
    }
    if (amount == 0) revert InvalidAmount();

    Property storage property = _getExistingProperty(propertyId);
    if (property.state != PropertyState.Closed) revert InvalidState();

    property.redemptionPool += amount;
    PAYMENT_TOKEN.safeTransferFrom(msg.sender, address(this), amount);

    emit RedemptionDeposited(propertyId, msg.sender, amount);
}
```

Note: **no** `whenNotPaused` / property pause check (deposits for exit should work under pause per redeem policy; if deposit should also work while paused — yes, allow deposits when paused so exit can complete).

- [ ] **Step 1: Implement `redeem`**

Place after `depositRedemption`:

```solidity
function redeem(uint256 propertyId, uint256 shares) external nonReentrant {
    if (!whitelisted[msg.sender]) revert NotWhitelisted();
    if (shares == 0) revert InvalidAmount();

    Property storage property = _getExistingProperty(propertyId);
    if (property.state != PropertyState.Closed) revert InvalidState();
    if (balanceOf(msg.sender, propertyId) < shares) revert InvalidAmount();

    _settleRevenue(propertyId, msg.sender);

    uint256 revenueAmount = accruedRevenue[propertyId][msg.sender];
    if (revenueAmount != 0) {
        accruedRevenue[propertyId][msg.sender] = 0;
        PAYMENT_TOKEN.safeTransfer(msg.sender, revenueAmount);
        emit RevenueClaimed(propertyId, msg.sender, revenueAmount);
    }

    if (property.redemptionPool == 0) revert NothingToRedeem();

    uint256 supply = totalSupply(propertyId);
    if (supply == 0) revert NoShares();

    uint256 payout = (shares * property.redemptionPool) / supply;
    if (payout == 0) revert NothingToRedeem();

    property.redemptionPool -= payout;
    _burn(msg.sender, propertyId, shares);
    PAYMENT_TOKEN.safeTransfer(msg.sender, payout);

    emit Redeemed(propertyId, msg.sender, shares, payout);
}
```

Important: `_burn` triggers `_update`, which settles again — safe because debt already synced and accrued was zeroed.
